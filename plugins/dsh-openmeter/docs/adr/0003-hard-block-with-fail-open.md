# 余额不足硬阻断，计费系统故障放行

客户预付余额（信用授予按用量扣减）耗尽时，插件拒绝发起新的模型调用（报错给 agent 与用户，运营者可解封/补额度），实现为带缓存的余额/访问权检查（约 60 秒 TTL，关键时刻强刷）。但 OpenMeter 本身不可达时放行并告警：计费系统的可用性故障不应终止对已付费用户的服务；故障期间的事件由 ADR-0002 的队列兜底，收入不丢。

## Considered Options

- 只警告不阻断——被否：产品化收款没有牙齿等于应收账款失控。
- 计费故障时也阻断（fail-closed）——被否：把计费系统变成服务的单点可用性瓶颈。

## Consequences

- 故障放行窗口内可能产生少量超支用量，属已知成本，由运营侧人工处置。
- fork 已提供信用预留（reserve-before-spend）机制，可天然防并发超支，留待 v2 评估，v1 不用。
