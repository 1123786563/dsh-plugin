# DSH OpenMeter 租户自助计费页设计

## 目标与范围

把 `dsh-openmeter` 的现有「计费」页面改为面向 SaaS 租户的自助“账单与用量”页。首屏优先回答：当前工作区还剩多少额度、按当前消耗是否会超出月度预算、主要由哪些模型产生费用；完整调用账本从首屏按需进入。

本次不实现支付、开票或自动充值。现有的 OpenMeter 客户创建、额度授予、人工阻断和预设归属是平台运营能力，不向租户暴露。

## 已确认的事实与风险

- 现有 `/api/openmeter/status`、`usage`、`customers`、`grants`、`block`、`bindings` 只做同源/回环检查；它们会返回所有客户或允许写入任意客户。
- 当前用量面板读的是进程内最近 500 条记录；重启后没有面向用户的历史账本。
- Casdoor 网关可在请求上提供已验签后的 `{ tenantId, userId, displayName, roles }`，但 stock DSH Web RPC 没有通用的 request-scoped Principal。自定义计费 HTTP 路由必须自行调用 `casdoorAuth.identityFromRequest()`，且验证失败一律拒绝。

因此，不能把现有全局端点换一套视觉样式后直接暴露给 SaaS 用户。

## 访问与归属边界

### 身份与授权

1. 新增租户端路由前缀 `/api/openmeter/me/*`。
2. 每个请求通过可选注入的 `casdoorAuth` 服务验证身份；服务缺失、令牌无效、未配置租户映射时分别返回明确的不可用、未认证、未开通错误，且绝不降级为 `house` 或全局数据。
3. 通过受运营者维护的 `tenantId -> OpenMeter subject` 映射把身份解析到唯一计费主体。映射是显式配置/开通数据，不能根据前端传入的 subject 推断，也不能在读取时隐式创建客户。
4. 预算读取对所有已认证租户成员开放；预算修改只允许 `tenantBillingManagerRoles` 中的角色。角色不匹配时页面只读。

### 平台运营能力

现有全局客户、grant、block 与 preset binding 路由迁移到管理员前缀，并以独立的运营者角色守卫。旧的未授权全局入口不保留兼容别名，防止客户端继续依赖跨租户能力。

## 读模型与 API

### 持久化租户读模型

新增 `TenantBillingStore`，持久化在插件 `dataDir`：

- tenant/subject 映射；
- 每个租户的月度 CNY 预算；
- 每条已提交的 assistant 消息对应的、可审计的用量账本行（时间、subject、provider、model、tokens、估算金额、币种）。

账本行在现有 WAL 记录成功构建的同一计量路径写入；以现有 `(sessionId, seq)` 去重键保证一次记录。它不替代 OpenMeter：OpenMeter 仍是额度和门禁的权威来源；该读模型只服务租户页面的按模型、按日与逐调用展示。历史从该版本启用起可用；不伪造启用前明细。

### 租户 API 合约

`GET /api/openmeter/me/summary?from=&to=` 返回：

- subject 对应 entitlement 的可用 Token 额度与 access 状态；Token 额度不得标注为 CNY；
- 当前周期的预算、已估算消费、剩余预算、预测月末消费、预计可用天数；
- 按模型的调用数、tokens、估算金额；
- 一个去敏后的服务状态（`healthy` 或 `degraded`）。

`GET /api/openmeter/me/usage?from=&to=&cursor=` 返回当前租户的时间倒序账本，包含按日小计。任何查询参数都不能指定 subject。

`PUT /api/openmeter/me/budget` 仅接受 `{ monthlyBudgetCny }`，仅预算管理员可写；金额必须为非负有限数。成功后返回更新后的摘要。

本期不提供真实“充值”写接口。界面的“充值额度”只在配置了外部结算入口时跳转；未配置时以非破坏性说明状态呈现，不能复用管理员 `grant` API。

## 页面与交互

一级设置页改名为「账单与用量」，保留 DSH 的浅色、克制外壳。

### 概览（默认）

1. 顶部：可用 Token 额度、基于近七天 Token 消耗的可用天数；主操作为“充值额度”，次操作为“查看用量明细”。CNY 只用于预估消费与预算，不能和 Token 额度混用。
2. 中部：本月预算进度和预测；预测超预算时以醒目的但非破坏性的警示说明，并为预算管理员提供“调整预算”。
3. 底部：模型费用分布表，展示模型、调用数、tokens、预估费用和占比。
4. 只显示面向租户的健康文案，禁止显示 WAL、门禁缓存、客户 key、内部户、价格刷新错误等实现细节。

### 用量明细

由“查看用量明细”进入。按日期分组，行内展示时间、模型、tokens、估算金额和可解释的调用来源；支持日期范围与分页。该页不出现其他租户或任何平台运营动作。

### 运营者设置

插件配置卡继续只服务平台运营者，并补充租户 subject 映射、可改预算角色与外部充值入口配置。它不挂在租户默认导航中。

## 错误、降级与兼容性

- 身份、映射或权限失败时 fail closed；绝不返回 house 或全部客户的数据。
- OpenMeter 临时不可用时，租户页显示“账单数据暂不可用”，不会暴露端点、令牌、WAL 或内部错误文本；模型调用维持既有的 fail-open 行为。
- 没有历史读模型时返回空明细和明确的“从启用日起统计”说明，不编造历史。
- 未安装 Casdoor 身份服务时，租户端路由不可用；管理员插件能力可以继续由受控部署单独使用。

## 验证策略

1. 单元测试：身份拒绝、tenant/subject 映射、角色检查、预算校验、账本去重、按 subject 过滤、预测计算。
2. 路由集成测试：两个租户分别请求摘要和账本；验证不能看到对方数据、不能伪造 subject、非管理员不能改预算、旧全局写入口不能被普通租户调用。
3. 前端测试：概要、警示、只读预算、空账本、受限充值入口、明细下钻和日期范围。
4. 人工浏览器验证：以两个不同租户登录，确认页面、主操作与数据隔离；另以运营者身份确认运营配置不出现在租户页。

## 非目标

- 支付网关、微信/支付宝、订单、发票和自动对账；
- 对已有 OpenMeter 历史记录进行无法证明的逐调用回填；
- 将 stock DSH 所有 RPC 自动改造成 request-scoped tenant authorization；
- 多实例共享账本存储。若部署扩展为多实例，`TenantBillingStore` 必须替换为共享、可审计的持久化实现后才能继续对外提供账本。
