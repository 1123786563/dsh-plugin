# dsh-plane v2：进程内 Plane 兼容引擎（零外部服务）

## 结论

把 `plugins/dsh-plane` 从"Plane REST 客户端"升级为**宿主进程内运行的 Plane 兼容引擎**：不启动任何独立服务（无 Python、无 Postgres、无容器），数据存本地 JSON 文件，实现 Plane `/api/v1` 兼容 REST 面（plane-mcp-server / plane-sdk / curl 可直接指向），现有 `plane_*` 工具族直连引擎，浏览器侧提供看板 UI。Plane 源码（makeplane/plane，Django/Python）仅作域模型与 API 契约参考，**不 vendor、不复制代码**（避开 AGPL 传染，插件保持 MIT）。原 remote 模式（Plane Cloud / 自托管实例）保留，`backend` 配置一键切换。

**已确认的技术依据**：Plane 后端 Django+psycopg 无法进 Node 进程，`pg_advisory_lock`/`ArrayField` 使 Postgres 无法 SQLite 化；官方 web 前端依赖数百个内部 API + live 协同协议，无法复用。dsh 插件是宿主 Node 进程内普通 ESM（无沙箱），webServer 可注册 prefix 路由自 serve 页面，自管文件存储有 openmeter WAL 先例。

## 架构

```
                      ┌─ 工具层 plane_*（现 11 个 + 新 2 个，零改动切换）
PlaneV1Router ────────┼─ webServer prefix /plugins/dsh-plane/api/v1/*（X-API-Key，供外部生态）
（进程内 v1 路由器）   └─ 测试（契约断言）

PlaneV1Router → PlaneEngine（域操作） → JsonStore（$DSH_HOME/plane/store.json，原子写）
backend: 'local'（默认）→ 引擎直调；'remote' → 现有 PlaneClient（fetch 远端）
```

关键设计：现有工具层全部是"构建 v1 路径 → `client.request()`"，因此引擎实现 `request(method, path, query, body)` 同签名即可；路由 handler 一份代码、三处消费（进程内直调 / HTTP 挂载 / 测试）。`work-items/` 与旧 `issues/` 路径段双接受（天然兼容现有客户端探测逻辑）。

## 文件级变更（plugins/dsh-plane/）

**新增 `src/engine/`** —— 本地引擎：
- `models.ts`：域类型，响应形状对齐官方 API reference（Workspace/Project/State/Label/Cycle/Module/WorkItem/Comment/Link；WorkItem 含 `sequence_id` 每项目自增 → `PROJ-12` identifier、priority、state、labels、start/target_date、sort_order、parent 自引用、is_draft、archived_at）
- `store.ts`：JSON 文件加载 + 原子保存（tmp+rename，.bak 备份），目录 `$DSH_HOME/plane/`（DSH_HOME 解析抄 openmeter `dsh-home.ts` 模式）；测试可注入内存实现
- `engine.ts`：域操作（CRUD、状态流转、cycle/module 挂摘、评论树、seed：首次初始化建 workspace `dsh` + 默认项目 `DSH` + 官方默认五状态组 backlog/unstarted/started/completed/cancelled）
- `pagination.ts`：cursor envelope（格式与字段名以官方 reference 为契约基准实现时逐端点核对）
- `search.ts`：按 name/description/identifier 搜索
- `key.ts`：本地 API key 生成/校验（`plane_local_` 前缀）

**新增 `src/api/router.ts` + `src/api/handlers/`** —— v1 路由器：路径解析分发 + 错误形状对齐 Plane；v1 端点范围（对齐 plane-mcp-server + 工具族所需）：work-items（CRUD/comments/search/identifier 查询）、projects（CRUD/lite）、states、labels、cycles（CRUD + cycle-issues 挂摘）、modules、members（list）、users/me；其余路径 404 带明确提示；`plane_request` 逃生舱自动获益。

**改 `src/config.ts`**：加 `backend: 'local' | 'remote'`（默认 local）；local 下 apiKey/workspaceSlug 由引擎管理/播种。

**改 `src/index.ts`**：backend=local 时构造引擎（含 store 目录、key 加载/生成），把 `PlaneV1Router` 包成与 `PlaneClient` 同签名的 backend 传给工具层；webServer 存在时挂 v1 HTTP 面（X-API-Key 鉴权）+ ui 路由 + 整页静态资源。

**改 `src/tools.ts`**：新增 `plane_create_project`、`plane_update_project`（双后端通用，remote 走 v1 projects 端点）。

**改 `src/routes.ts`**：panel 路由改走 backend 抽象；新增 `/plugins/dsh-plane/ui/*`（宿主侧直调引擎，浏览器不持 key，与 panel 同防线）。

**浏览器半区**：
- 改 `src/client/form.ts` + 设置卡片：backend 切换、local 模式显示引擎状态（工作区/数据量/API key 查看/重置/数据目录）、remote 维持现有字段
- 改 `src/client/panel.tsx`：加内联创建工作项、状态/优先级快改
- 新增 `src/app/`：整页看板（独立 esbuild 入口 `lib/app.js`，prefix 路由 `/plugins/dsh-plane/app` serve HTML；列表 + 按状态分组的看板视图 + 工作项详情/评论；React，数据走 ui 路由）；面板放"打开完整看板"链接

**构建/文档**：`scripts/build-client.mjs` 加 app 入口；`README.md`/`README.zh.md` 重写 local 引擎章节（声明：兼容实现，非 Plane 代码，不受 AGPL 约束）；根 `README.md` 表格同步。

## 实现顺序

1. `engine/`（store→models→engine→pagination/search/key）+ vitest 单测（域操作、分页、sequence 发号、seed 幂等、崩溃写安全）
2. `api/router` + handlers + 契约测试（响应形状、cursor、错误、双路径段）
3. backend 分流接入工具层 + 配置 + 工具测试双后端跑（remote 侧现有 fetch stub 不动）
4. webServer 挂载（v1 面 + ui 路由）+ key 鉴权测试
5. 设置卡片 + 面板增强（form/panel 测试更新）
6. 整页看板（app 入口 + 路由 serve + 冒烟）
7. 文档 + `pnpm build && pnpm test && pnpm typecheck` 全绿

## 验收

- 全套测试绿；`backend: 'local'` 下 11+2 个工具不开任何端口即可用
- curl 冒烟：`X-API-Key` 调 `/plugins/dsh-plane/api/v1/workspaces/dsh/projects/` 走通 CRUD
- 浏览器：设置卡片切换 backend、面板快改、`/plugins/dsh-plane/app` 整页看板可用
- 兼容性（尽力项）：官方 plane-mcp-server 指向本地 v1 面跑通基本操作
- 安装 web profile：`pnpm dsh plugin --profile web add link:...` 后重启 dsh web 验证

## v2 范围外

Pages/Views/Intake/Relations、附件上传、webhook、多用户 assignee（casdoor principal 映射）、协同编辑、remote→local 数据迁移工具、fields/expand 裁剪。

## 风险与对策

- v1 响应形状逐端点对齐是体力活 → 以 developers.plane.so API reference 为唯一契约基准，实现时逐端点核对，不确定的字段宁缺勿造
- 整页自 serve 无先例 → 机制已验证（prefix 路由 + 独立 bundle），M6 独立成步，失败则退化为面板内嵌完整 UI
- store.json 损坏 → 加载失败时从 .bak 恢复，仍失败则报错而非清空
